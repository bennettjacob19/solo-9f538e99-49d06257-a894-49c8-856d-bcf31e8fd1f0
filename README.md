# 遥测 UDP 代理（接收器 A/B 切换）

遥测终端经 UDP 代理把短报文发给接收器，值班员在网页上切换接收器 A/B，
已建立的会话不受影响，回包不会送错设备。

## 组成

| 组件 | 说明 |
|---|---|
| `proxy/` | asyncio UDP 代理 + Flask 操作网页 + SQLite 持久化 |
| `receiver/` | 本地接收器，原样回显报文，可延迟回包；固定源端口模式下核对来包源端口 |
| `docker-compose.yml` | 一键启动代理 + 接收器 A + 接收器 B |
| `scripts/verify_local.py` | 无 Docker 环境下的端到端行为验证 |
| `scripts/verify_fixed_mode.py` | 固定源端口模式的端到端验证 |

## 启动

```bash
docker compose up --build
```

- 操作网页：http://localhost:8080
- 遥测终端发送地址：`UDP <宿主机>:9000`

## 行为规则

- **会话**：按客户端 `IP:端口` 建立，空闲 5 秒（`SESSION_IDLE_TIMEOUT`）无收发即过期。
- **建会话时固定接收器**：会话期间的一切报文都发往建会话那一刻的目标接收器；
  网页切换 A/B 只影响之后新建的会话，旧会话继续走原接收器直到过期。
- **原样透传**：报文与回包内容不做任何修改。
- **回包不错投**：每个会话使用一条独立的、已 connect 到其接收器的上游 UDP
  套接字（独立本地端口），只有该会话对应接收器的回包会被送回该客户端。
- **迟到回包**：会话过期即关闭其上游端口，端口进入冷却期
  （`UPSTREAM_PORT_COOLDOWN`，默认 30 秒，应大于最大回包延迟）不再分配；
  因此相同 `IP:端口` 重建的新会话也不可能收到旧会话迟到的回包。
- **切换可靠性**：切换先写 SQLite 再生效，保存失败保留原目标并在网页报错。
- **重启**：目标接收器保存在 SQLite（`proxy-data` 卷）重启后保留；
  会话全在内存，重启即清空。

## 固定源端口模式

接收器所在网段只放行代理的一个 UDP 源端口时使用（网页上"启用/关闭"，
默认由 `FIXED_SOURCE_PORT_ENABLED` 决定首次启动状态，之后以 SQLite 中的开关为准）。

- **唯一源端口**：启用后代理无论上游是 A 还是 B，都从同一个 UDP 端口
  （`FIXED_SOURCE_PORT`，默认 9500）发送；所有会话共用这一个套接字。
- **接收器核对来源端口**：接收器（`ALLOW_SOURCE_PORT`，默认 9500）只接收源端口
  等于约定端口的报文，其它来源丢弃并记日志；回包发回该来包的实际源地址。
- **会话区分**：代理在每条转发报文前加 20 字节会话标识
  （`TLM1` + 16 位十六进制随机数）；接收器回包时把标识带回，并附加
  `SRC` + 2 字节观测到的源端口。代理按标识把回包交给原会话并剥除附加信息，
  **终端始终只收发原始字节**。因此两台终端发相同报文、回包乱序，也各归各会话；
  回包还会核对来源确实是该会话的接收器。
- **大小上限**：固定端口模式下只转发不超过 `MAX_FORWARD_SIZE`（默认 1400）
  字节的终端报文，超限丢弃并在网页日志记明原因。
- **切换**：A/B 切换只影响新会话；固定端口模式开关本身会重建全部会话。
- **旧回包不投递**：会话标识随会话过期销毁；代理重启后所有标识失效
  （随机数保证不复用）。所以会话过期或代理重启后，即使终端用原端口重连，
  迟到的旧回包也会因找不到标识被丢弃并记日志。
- **端口被占用**：固定端口绑定失败时网页明确报错，模式保持"启用但不可用"，
  代理**不会**换端口继续转发（报文记"丢弃"）；释放端口后可在网页重新启用。
- **关闭后**：恢复原来的每会话独立上游端口转发方式。

> 注意：接收器的 `ALLOW_SOURCE_PORT` 与代理开关是两侧独立配置。compose 默认两侧
> 都启用固定端口 9500。若在网页关闭固定端口模式后要真正回到原转发方式，
> 还需把接收器的 `ALLOW_SOURCE_PORT` 留空（`ALLOW_SOURCE_PORT= docker compose up -d`）
> 并重启接收器，否则接收器仍会拒收非约定源端口的报文。

## 网页功能

- **切换目标接收器**：一键切换 A/B。
- **固定源端口模式开关**：启用/关闭，失败原因在网页显示。
- **并行试传（两路实际 UDP）**：两路分别设置报文、回包延迟、客户端端口，
  同时发出；结果分别显示实际去向接收器、接收器观测到的源端口、回包内容与 RTT。
  - 不填端口：每次试传都是新会话（走当前目标）。
  - 填同一端口：空闲 5 秒内复用旧会话（仍走旧接收器）；
    配合"回包延迟 > 5 秒"可现场观察旧会话迟到的回包被丢弃。
- **活动会话 / 报文日志**：实时查看每个会话固定的接收器、模式、发送源端口、
  每条报文的实际去向与回包（每 2 秒自动刷新）。

## 接收器延迟回包

- 环境变量 `REPLY_DELAY`：该接收器所有回包的默认延迟秒数。
- 报文级覆盖：报文以 `DELAY:<秒>:` 开头时按该值延迟（回包仍是完整原始报文）。

## 配置（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `UDP_LISTEN_PORT` | `9000` | 代理对终端的 UDP 监听端口 |
| `HTTP_PORT` | `8080` | 操作网页端口 |
| `SESSION_IDLE_TIMEOUT` | `5` | 会话空闲超时（秒） |
| `RECEIVER_A_HOST/PORT`、`RECEIVER_B_HOST/PORT` | 见 compose | 接收器地址 |
| `DB_PATH` | `/data/proxy.db` | SQLite 路径（目标与模式开关持久化） |
| `UPSTREAM_PORT_MIN/MAX` | `20000/29999` | 上游本地端口池（非固定端口模式） |
| `UPSTREAM_PORT_COOLDOWN` | `30` | 上游端口关闭后的冷却秒数 |
| `FIXED_SOURCE_PORT_ENABLED` | `0`（compose 中为 `1`） | 首次启动时是否启用固定源端口模式 |
| `FIXED_SOURCE_PORT` | `9500` | 固定端口模式下唯一的 UDP 源端口 |
| `MAX_FORWARD_SIZE` | `1400` | 固定端口模式单条终端报文上限（字节） |
| `SESSION_TAG_MAGIC` | `TLM1` | 会话标识 4 字节 magic（代理与接收器须一致） |
| 接收器 `ALLOW_SOURCE_PORT` | 空（compose 中为 `9500`） | 只接收该源端口的报文；留空=不校验 |

## 本地验证（无需 Docker）

```bash
pip install flask
python3 scripts/verify_local.py        # 原转发方式 / A-B 切换 / 迟到回包 / 重启
python3 scripts/verify_fixed_mode.py   # 固定源端口模式全部行为
```

`verify_local.py` 逐项验证：原样透传（含二进制）、切换后旧会话走原接收器、
过期后新会话走新接收器、迟到回包不投递、网页试传、重启保留目标并清空会话、
保存失败保留原目标。

`verify_fixed_mode.py` 逐项验证：接收器拒绝非约定源端口、启用/关闭开关、
相同报文与乱序回包按会话交付、1400 字节上限与超限日志、切换只影响新会话、
过期/重启后旧回包不投递、固定端口被占用时网页报错且不换端口、
网页并行两路试传的实际接收器与观测源端口、关闭后恢复原转发方式。
